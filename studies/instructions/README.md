# Instruction studies

This bundle contains the saved 100-proof and 60-claim instruction studies, all four instruction arms, model answers and model grades, task inputs, recorded usage, and corrected accounting. It also contains source-validity and tool-use sensitivities, including the 60 of 78 outputs graded as matching references subsequently invalidated by source or witness review.

Run `python studies/instructions/replay.py` from the repository root (Python 3.9+; standard library). It checks all seven saved original summaries, reproduces their output-token ratio bootstrap intervals, the 720 corrected claims60 cell aggregates, and the 60/78 diagnostic. It does not call a model or change any judgment. For the published corrected full-token and source-validity intervals, run `python studies/instructions/replay_intervals.py` with NumPy installed. That second entry point reproduces the original 20,000-resample analyses from the saved per-task data and original arithmetic helpers.

`reproduction/prompts.json` supplies exact methods and grading rubrics; `schema*.json` specifies outputs. `original/` preserves the initial Opus cells and their original grades. `reproduction/grades/proofs100_task1/` contains the separately designated regrading used in the source-validity diagnostic. `reference_validity/stratified_primary.json` and `toolfree_sensitivity.json` retain all published subsets and intervals. `corrected_claims60_accounting/RESULTS.json` gives all accepted and rejected attempt components, null unknown usage, corrected ratios and interval specifications. Corrected full-token accounting takes precedence over older full-token fields in `reproduction/summary/`; the original output counts remain unchanged.

The source scripts are provided for inspection and adaptation. Their original research-tree paths are anonymized placeholders, so they are not the portable entry point. The replay above uses only files shipped here. Full model execution requires the model versions/CLI settings in the manuscript's instruction-study procedures; model services are not required to reproduce saved tables. Rejected/provider event streams are excluded; their recorded numerical accounting is retained in the saved result files. Native usage identity/log-detail fields and machine paths were projected out without changing numeric components, answers, or grades. Source hash fields describe original input bytes; the repository manifest hashes the distributed bytes.

## Grader-call chronology

`reproduction/grader_cohort.json` distinguishes the September 15 grading pause from the later completed dataset. The pause has 1,700 completed grading cells, six with recorded shell commands (ten command invocations), plus six failed and two rate-limited attempts outside that completed-cell denominator. The saved dataset later reached 1,920 completed cells; the later 220 include one additional command-bearing cell. This pause cohort is a retrospective reconstruction from timestamped ledgers and the recorded pause; no original prespecified 1,700-cell freeze was found.

`reproduction/grade_usage/` provides numerical native usage, model settings, command counts and the recorded command text for each completed cell. `reproduction/grader_ledgers/` retains status, chronology, prompt stamps and source hashes while omitting service identities and workdirs. Commands are quoted study evidence and are never executed by the replay. Original hashes describe original source bytes; `../reviewed_projection_bindings.json` maps them to the anonymous distributed copies.

Run `python studies/replay_reviewed_projections.py` to check these cohort joins, the added source bindings, and the twelve all-instruction full-token component rows. The all-arm/no-hint/execution sensitivity provenance is in `corrected_claims60_accounting/claims60_story_reanalysis.json`, with its original arithmetic source in `source/reproduce_claims60_story.py`.
