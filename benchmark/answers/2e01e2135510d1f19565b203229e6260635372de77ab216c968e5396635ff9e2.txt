1. His own inputs on all t instances: ℓ^{1,1}, ..., ℓ^{k,1}, ..., ℓ^{1,t}, ..., ℓ^{k,t}.
2. Alice's inputs on the (T+1), (T+2), ..., t instances: s^{1,T+1}, ..., s^{k,T+1}, ..., s^{1,t}, ..., s^{k,t}.
3. The index T.

Alice knows her inputs on all t instances: s^{1,1}, ..., s^{k,1}, ..., s^{1,t}, ..., s^{k,t}.

The output is OR-Index^{m,k}((s^{1,T}, ..., s^{k,T}), (ℓ^{1,T}, ..., ℓ^{k,T})), which depends only on Alice's inputs on the T-th instance and Bob's inputs on the T-th instance.

In the protocol, Alice sends a message M to Bob based on her inputs s^{1,1}, ..., s^{k,1}, ..., s^{1,t}, ..., s^{k,t}. Bob then uses his inputs ℓ^{1,1}, ..., ℓ^{k,1}, ..., ℓ^{1,t}, ..., ℓ^{k,t}, the index T, the inputs s^{1,T+1}, ..., s^{k,T+1}, ..., s^{1,t}, ..., s^{k,t}, and the message M to compute the output.

Since Bob already knows s^{1,T+1}, ..., s^{k,T+1}, ..., s^{1,t}, ..., s^{k,t}, Alice doesn't need to send information about these in her message. So the message M will depend only on s^{1,1}, ..., s^{k,1}, ..., s^{1,T}, ..., s^{k,T}.

In the embedded protocol π_{j,s} for OR-Index^{m,k}, if j ≤ T, then the message M will depend on s^{1,j}, ..., s^{k,j}, but also on the other inputs s^{i,1}, ..., s^{i,j-1}, s^{i,j+1}, ..., s^{i,T} (for i=1,...,k). This means that the message depends on additional inputs beyond s^{1,j}, ..., s^{k,j}, which are not part of the input to OR-Index^{m,k}.

So the protocol π_{j,s} is not a valid protocol for OR-Index^{m,k} when j ≤ T, because the message depends on additional inputs.
