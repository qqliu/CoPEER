Code, data and reproduction

Everything behind the numbers

The public repository holds the paper, this website and the released evidence: the dossiers, their numbered sources and Lean certificates, the human-review records, the localization benchmark with its saved answers, the instruction, repair and retrieval studies, the executable checkers, and the Lean sources of the mathematical follow-ups. Saved-result replays recompute the reported quantities without making model calls.

Verify and replay

Commands, from the repository root

Python 3 with its standard library is enough for the verifier and the saved-result replays. Lean compilation additionally requires the pinned toolchain described in bugbank/lean/README.md.

Integrity of the distributed files

python3 -B tools/verify.py --strict

The human-approved core and its benchmark scores

python3 -B bugbank/core/verify.py --release .
python3 -B benchmark/core/replay.py --release . --membership bugbank/core/membership.json --output /tmp/core_scores.json --with-intervals

The replay reparses the saved selections, checks the exact answer files, recomputes Hit@1 and Hit@3 for every reporting view and compares them with benchmark/core/expected_scores.json, the same file this website reads. Without --with-intervals the script deliberately skips the clustered bootstrap and the interval comparisons (a counts-only replay); with the flag it recomputes the 95% intervals as well.

Review evidence and the formal inventory

python3 -B bugbank/reviews/reproduce.py --check
python3 -B bugbank/lean/replay.py --check-inventory

The studies

Each study directory under studies/ has its own README with inputs, analysis code, saved results and the replay command: studies/instructions/ (the four-arm instruction study and the 60-statement panel), studies/executable_checks/ (the 604 executable tasks; count replay), studies/repairs/ (16 Lean repair tasks; fresh checking needs Lean 4.30 and bubblewrap), studies/proof_development/ (50 paired tasks per model with the 661-entry retrieval snapshot), studies/open_problem_retrieval/ (the five cohorts of paired targets), studies/response_review/ (the LLM review of saved responses, Experiment B), studies/criticism_endpoints/ (the criticism and paired-comparison bounds computed from that panel), studies/audit_tests/ (the six-fixture check of the publication and scoring procedure).

Lean

Certificates and toolchains

Corpus certificates compile under Lean 4.30.0; the mathematical follow-ups record their toolchains per file (core Lean 4.30.0 and 4.34.0; the layered-boundary results use Lean 4.30.0 with Mathlib). Axiom audits record, for every selected declaration, the axioms used; the explorer shows them per record. No certificate uses sorryAx; native reduction is flagged where a declaration relies on it.

Website data provenance

How each number on this site is traced

Tables shown on the site are parsed from the LaTeX source of the paper (commit cb9312a) by tools/extract_paper_tables.py; each generated file records the table label, the line range in main.tex and the caption, and docs/data/MANIFEST.md lists their hashes. The explorer and the exercise read the released evidence through tools/build_site_data.py, which joins the current review layer to each record by id and asserts that the released core scores equal the paper's Table 16. The laboratories compute live from assets/js/math/labs.js; the self-checks page compares them with the paper's statements and with independently generated fixtures.
